# 目前功能與使用方式

更新日期：2026-10-01。第三階段程式已部署至 VM，版本 `b4dd278`；實際版本與驗收以 [implementation-plan](implementation-plan.md) 為準。

這個專案目前可以做兩件事：**集中多平台兼職機會，減少逐站搜尋；把本人準備提案、投案與跟進的紀錄放在一起。**

## 1. 找兼職與管理機會

### 多平台收案

- 將已接入平台的公開 API、RSS、公開頁面或指定職缺通知集中到同一份清單。
- 增量保存職缺與來源紀錄，同一內容重讀不重複新增。
- 平台分別回報讀取結果，單一來源失敗不代表所有來源都失敗。
- 各平台是否接入、讀取限制與下一個驗收關卡，查 [全部平台接通主表](platform-connectivity.md)。研究名單不等於已接入來源，有限讀取也不代表全站覆蓋。

### 搜尋、篩選與排序

- 搜尋職稱、公司或技術關鍵字，按平台與合作型態篩選。
- 切換「待看／收藏／已略過／全部」清單。
- 在「篩選設定」調整工作類型、每週工時上限及固定專案最低台幣預算；工時預設 30 小時，可調整或取消。
- 顯示推薦排序、匹配理由、工作內容、報酬、工時、地點及台灣資格依據。
- 資料缺漏時顯示「待確認資訊」，不把未知條件當作已符合，也不把 remote 當成全球都能承接。

### 分組、差異與收藏

- 相同職缺集中顯示，保留各平台原文連結。
- 同職缺的通知內容不同時，保留各份內容並標示差異欄位；不由轉寄時間判定哪份較新。
- 可收藏、取消收藏、略過及恢復待看。收藏只表示值得評估，並不代表已投案。
- 原文連結供本人核對有效期限、資格與工作需求。

## 2. 每日摘要與運作狀態

- 每天台北時間 09:00 排程收集已配置來源，產生職缺摘要並沿既有設定寄送。
- 摘要呈現機會、匹配資訊及原文連結；不夾帶提案正文。
- 探索頁分開呈現來源最近檢查、每日執行及摘要寄送結果。
- 同一已知內容避免重複通知；通知內容變更可在後續摘要再次出現。
- 來源不完整與摘要寄送結果分開判斷；中斷或結果不確定時不自動重跑／重寄。

容器 healthy 或排程已啟動，並不代表當日全部來源成功或收件者已收到信。

## 3. 投案紀錄與跟進

### 記錄實際投案

- 從職缺詳情記錄已投案，關聯該職缺的來源紀錄。
- 也可直接新增手動機會或熟人轉介，不需要先建立平台職缺。
- 填寫機會名稱、公司／聯絡對象、原文連結、投案日期、階段、下次跟進日期與備註。
- 階段為「已投案／洽談中／已承接／結束」，可更正紀錄或刪除清單中的紀錄；保留稽核歷史。
- 可關聯客戶、聯絡人、所選提案版本，以及可用的送出證據。
- 已記錄投案的來源群組退出待看候選及後續新摘要；既有摘要不改寫。

投案紀錄由本人填寫，不自動追蹤原平台上的回覆或案件階段。

### 統計與待跟進

- 顯示本週已記錄投案件數、待跟進件數與逾期件數。
- 按階段篩選，或只查看到期的跟進事項，依跟進日期排序。
- 導覽列顯示待跟進數量；更新日期或階段後，統計隨查詢更新。
- 「已承接／結束」及已刪除紀錄不列入待跟進。

提醒目前在站內顯示，沒有另外寄送跟進 Email，也不自動聯絡客戶。

## 4. 客戶與聯絡人

- 建立、修改及封存客戶；每個客戶可有多名聯絡人。
- 聯絡人可填名稱、聯絡方式及備註，儲存聯絡方式不會觸發寄信。
- 客戶詳情可查看其關聯投案。
- 投案可指定一名主要客戶及該客戶下的一名聯絡人，也可不指定。
- 舊投案保留關聯當時的名稱／聯絡資訊，客戶更名或封存不改寫歷史。
- 同名客戶或相同聯絡方式不自動合併。

## 5. 提案模板與草稿

- 從探索機會準備草稿，或直接撰寫不帶平台來源的手動草稿。
- 建立、修改、封存純文字模板，預覽填入欄位後的正文。
- 模板支援機會名稱、客戶稱呼、合作方式、本人作品及本人報價；未填欄位明示待填。
- 每次儲存正文新增版本，舊稿可查看；重新套模板也建立新版本。
- 可選擇並複製某一版正文，到原平台自行投案。
- 實際投案後，可將所選版本關聯到投案紀錄。
- 封存草稿保留歷史版本及送出紀錄。

草稿由本人撰寫與審閱，目前沒有 AI 生成、自動補個人經歷或自動報價。建立草稿、複製正文都不計為已投案。

## 6. 外部送出：已備妥但未啟用

外部送出頁目前可以準備與核對內容，**Email／Freelancer 尚未登入、配置或完成真實通道驗收，確認送出會被阻擋。**

程式已具備以下流程，供後續啟用：

1. 選擇一個確定的草稿版本。
2. 填寫 Email 收件者／主旨，或 Freelancer 案件、投標金額、期程與費用確認等資料。
3. 查看帳號、環境、目的地及完整正文。
4. 核准這份精確內容，再另行確認送出。
5. 查看接受、拒絕或結果不確定的紀錄；不確定時人工核對，不自動重送。
6. 實際投案後另建立投案紀錄，保留版本及證據；記錄投案不會再次送出。

Email 的接受證據只表示 SMTP 接受，不代表送達或已讀。Freelancer 另有管理用的唯讀 bid 查證工具，操作見 [Compose 文件](compose.md)。

## 建議日常使用流程

**看摘要／探索清單 → 收藏 → 核對原文 → 準備草稿 → 回原平台投案 → 記錄投案 → 到期跟進。**

每週查看實際投案件數及回覆進度，選擇下一批值得投案的機會。每週三件可作為節奏參考，系統沒有強制配額或自動投案。

## 如何開啟

前端與後端都部署在同一台 VM；目前前端只開放 loopback，透過既有 SSH tunnel 存取：

```bash
ssh -N -L 127.0.0.1:3327:127.0.0.1:3327 oci-a1
```

保持連線，開啟 `http://127.0.0.1:3327`。本機啟動與離線合成 Demo 見 [README](../README.md)；Demo 不讀憑證、不接來源、不寄信。
